# v1.5.5

## 主要变化

- 修复 Pi 会话被一次卡死的运行彻底毒化的问题。当上一次运行在压缩上下文途中被桥接结束回合时，如果该压缩没有响应中止信号，agent 的 activeRun 集合将永远无法清空，之后每条消息都会报 `Agent is already processing`，只能重启客户端进程才恢复。现在遇到这类忙碌错误会先给出一次宽限期（20 秒内反复发送 abort 信号）等待运行自行转为空闲，若成功则原地重试；若仍未空闲，则释放这个卡死的 AgentSession，并基于同一会话文件重建（全新的 agent 状态、从磁盘恢复完整记录），然后重试一次消息。没有对应文件的纯内存会话会直接以原始错误结束该回合，不再循环。
- 升级 Pi 运行时依赖 `@earendil-works/pi-coding-agent` 至 0.99.1（发布线此前固定为 0.85.1）。
- 启动 banner 与 `/status` 现在带上构建指纹，形如 `TLive Bridge v1.5.5 (<提交> @ <分支或标签>) started`。版本号是在构建时注入产物内部的，与安装目录名和目录内的 package.json 都无关，因此此前无法回答“正在运行的 dist 究竟来自哪次提交”。现在可以直接追溯来源；CI 在标签上构建时会标注标签名，而不是 detached HEAD 的字面量 `HEAD`。
- 补充构建指纹注入及其降级路径的回归测试。

## 验证

- `npm run test:coverage`：通过。
- `npm run build`：通过。
